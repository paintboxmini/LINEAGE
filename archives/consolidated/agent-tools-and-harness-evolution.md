# Agent Tools & Harness — Design Trail

## What this trail preserves

This is the historical evolution of the tooling and process layer that sits around canon — `agent-tools/`, `rules/invariants.md`'s own doctrine status, and the naming/taxonomy work that kept them from drifting into each other. It is distinct from the Canon Gate and the Translation Principle, which have their own consolidated files (`canon-gate.md`, `translation-principle.md`) — this file is about the machinery and the process that built, corrected, and eventually cut down that doctrine, not about the authority model itself.

The current tools are authoritative elsewhere (`agent-tools/README.md`, `CLAUDE.md`). This file preserves the reasoning trail: why each tool exists in the shape it does, what got tried and rejected, and why most of the doctrine layer this trail describes is no longer live.

## Red-team: from "find mistakes" to "attack invariants"

`agent-tools/red-team.md` began as a content-layer review: ambiguity, redundancy, tone, mechanical weakness, keyword compliance, visible reasoning, with a floor requiring at least three issues found. That was the right shape for the early wording-and-redundancy phase of the repo.

It stopped being the right shape once the combat simulator started exposing rule architecture, timing policies, and emergent interactions — the deepest recent bugs were invariant violations (Predictable breaking blind simultaneity), which the old checklist would have missed entirely. Via a GPT review, the tool was rebuilt around a different center of gravity: invariant violations checked first (does this hide a rule change, a new timing window, an engine special-case, an implied new policy — name the invariant and ask if it should be a temporary rule modifier), then simulation abuse (exploit it in `combatsimulations/` if testable, else reason degenerate lines by hand and say which), then mechanical relevance split from identity (does it matter vs. is it a decision nothing else creates), ambiguity split into rules-ambiguity vs. natural-language-ambiguity, and an evolution check asking what a card mutated from and whether it's a mutation or a duplicate. A required generative finding — an unintended interaction, possibly the best idea in the pass — was added on top. Findings got ranked Critical/Moderate/Cosmetic instead of receiving equal effort regardless of severity, "leave it alone" became a valid verdict once the forced three-issue floor was dropped, and the pass closed on a stated philosophy: assume content is intentionally minimal, add complexity only to solve a demonstrated problem.

The first live shakedown was Gambler's Ruin. The invariant pass came back clean (a custom damage hook, no new timing or policy). The simulation pass ran for real: mean 8.70 damage, range 6–17 at Body 4, the max-3 reroll cap load-bearing, balance-neutral against Steele within ±1%. The verdict was leave it alone — the tool correctly declined to invent an edit, and Drew confirmed the card's "ruin" is just the variance downside of relying on it and rolling low, with the mitigation ordering already correct. (Max damage: 17 = 4 body + three odd rerolls at 3 each + a free final die of 4.)

## Prompt-refinement: from "fix the prompt" to "find the bottleneck"

`agent-tools/prompt-refinement.md` originally asked two questions — what was unclear, missing, or inefficient, and what one improvement should be made to the prompt or workflow — which implicitly assumed the prompt itself was always the problem and biased every fix toward prompt-engineering.

The real fix is sometimes not a prompt edit but a missing artifact entirely: a canonical timing document, an engine-invariant doc, a structural change. The tool was widened, again via a GPT review, to ask where the actual bottleneck is — prompt, missing repo context, missing docs, workflow, or something else — and to require preferring repo-structure, documentation, or workflow fixes over wording tweaks, with an explicit anti-inflation rule: don't add an instruction if better repo structure or docs would solve it, because a prompt that only ever grows is a prompt going wrong. The tool kept its real stopping criterion: if no meaningful improvement exists, return nothing — silence means the process has converged.

Both this upgrade and red-team's were the same underlying move: the repo was starting to build processes that improve themselves, optimizing the next thousand runs instead of just the current one.

## `rules/invariants.md` created

The prompt-refinement pass had, in effect, predicted its own next artifact — "sometimes the fix is a missing invariant doc, not a prompt tweak" — and Drew called it on the very next turn. Before this, the engine's core assumptions lived only in code, scattered across `combat.md`, `core-rules.md`, `card-glossary.md`, and memory; red-team's new invariant-violation pass had no canonical target to check findings against, and rule-bending cards had no declared list of what they were allowed to bend.

The first version of the file established one canonical, engine-scoped list: the exchange as an ordered resolution loop (declare, blind simultaneous selection, RPS, apply outcome, damage pipeline) with each step's known modifiers named beneath it; standing invariants (wheel and marker, blocking costs a card, derived stats, deck cycles, private-then-public reveal); and a rule-modifier registry table mapping keywords like Predictable, Axiom, Interrupt, Stagger, Initiative Shift, Armour, Resist, Fortress, Intercept, Shared Burden, and Evade to the invariant they bend and their lifetime — the literal seed of a later flags-to-typed-modifiers-to-policy-stack architecture. `red-team.md`'s "check against" pointer was wired to it, closing the loop. The damage pipeline order was verified against both simulator engines' `deal()` functions in the same pass: redirect, then volunteer-shield, then Armour, then Resist, then floor, then apply — Armour before Resist, a single hit clamped to zero, unpreventable damage skipping Armour and Resist both.

This first version did not survive intact — see the two later passes below, which found the file was still leaking scope it didn't own.

## Design/name housekeeping: "exemplar" and "design principles"

Drew flagged a pattern in himself worth checking rather than accepting on faith: "I misuse words that have a clear definition... whatever the word exemplar is supposed to mean, I don't got it... design principles is actually more technically correct" than philosophy. Both claims were checked against the dictionary rather than agreed with reflexively.

"Exemplar" held up: the dictionary sense — "one that serves as a model or example... an ideal model," from Latin *exemplar*, "pattern, model" — matched Drew's own gloss ("the embodiment of the ideal") almost exactly. The word wasn't the bug; the file `exemplars.md` was, because it had been made to carry two different concepts (an efficiency crib and a curated best-content register) under one filename until the word had to serve both jobs at once. That conflation is untangled properly in its own section below.

"Design philosophy" vs. "design principles" was the one Drew called correctly: philosophy names an overarching worldview, principles name discrete, independently-checkable statements — and the file in question was a flat list of eight independently-testable bullets, not a unifying worldview paragraph. `agent-tools/design-philosophy.md` was renamed to `agent-tools/design-principles.md`, and all nine referencing files were swept (`CLAUDE.md` four times, `rules/invariants.md`, `exemplars.md`, `README.md`, `compiled-crib.md`, `red-team.md` three times, both generators), plus one stray "design-philosophy principle" phrase inside the Translation Principle's own prose. Confirmed clean by a full-repo grep both before and after.

## Exemplars split from the compiled crib

Drew's own definition made the conflation explicit: "exemplars mean one thing to me. examples that are the embodiment of the ideal... specifically for Tales Untold content only. The best examples of content." Confirmed on the spot: the Fencerow Shrike is an exemplar.

That is genuinely different from what `exemplars.md` had become by then — a practical efficiency crib (engine facts, difficulty-metric calibration, format templates) that happened to be built under the same filename because both concepts pointed at overlapping material. The two were split: `agent-tools/exemplars.md` was renamed to `agent-tools/compiled-crib.md`, unchanged in function, and reframed as a cross-cutting utility rather than one of the doctrine's own canonical kinds. A new, short `agent-tools/exemplars.md` was written from scratch, content-only: a Confirmed section (the Fencerow Shrike, with the specific design principles it demonstrates named) and a Candidates section (Weck, flagged as a proposal, not yet confirmed — the same discipline the invariants file used for its own unconfirmed candidates).

This split was itself provisional. The whole doctrine layer it belonged to was cut down to scar tissue not long after (see below), and `exemplars.md` was eventually deleted entirely in an unrelated branch merge — the split's actual endpoint, worth naming plainly rather than dwelling on.

## Two admissions from Drew

Logged as fact, not softened, because they explain how a specific piece of canon came to exist rather than functioning as a new procedure. First: "I let GPT influence things they clearly didn't have the context for" — the four-layer taxonomy that kicked off the three-pass invariants correction (below) arrived via a GPT message Drew relayed, and GPT was reasoning about this repo's architecture without the context this session actually had. Second: "Auth level gating wasn't respected by me" — Drew, as the Authority-3 holder, let that external framing carry more weight into canon than it had earned, rather than checking it against full context first.

Neither admission rewrote a rule. The three-pass correction that followed them is itself the evidence that the system's real safeguard — cheap, reversible iteration — caught what up-front gating hadn't.

## Invariants.md, second and third passes

**Second pass.** Drew: "I still feel like our workflow is muddy... this is a step in the right direction." Four corrections landed the same day. The Initiative Shift and Staggered worked examples were removed from the file entirely — Drew: "those were my examples that don't fit the actual resolution level invariants are supposed to operate at" — leaving the prime invariant to stand alone, self-defining, in his own sharper wording: "mechanics exist to ensure that they reflect the fantasy of the TTRPG." "Rule bending cards don't temporarily swap invariants" was fixed as a category error — invariants can't bend, cards override specific mechanics, and the invariant is only ever the yardstick a new mechanic gets checked against — so the registry's "Invariant bent" column became "Mechanic overridden" throughout. Using the combat simulator as a self-verification step when implementing rulings was cut as a real, named workflow bug — the sim was always supposed to be Drew's separate instrument, not the agent's validation gate. And the deeper bug: authority gating had been creating friction on Drew's own direct statements, treating something he'd stated outright as an unconfirmed aside needing a round-trip before it counted — fixed by drawing an explicit line between Drew stating something new (apply it, flag it, let him revert) and the agent inferring or paraphrasing something ambiguous (the actual case that deserves a pause).

**Third pass.** Sharper still: "invariants should only be for the combat simulator... it's a mathematical truth underneath the player-facing mechanics." Drew's own worked exemplar — the engine tracks a turn-count per combatant, a human tracks the same thing by looking at a wheel, the invariant is that the count stays correct regardless of which visualization a human uses — was a genuinely different kind of claim than anything previously in the file: a computational fact of the form "player visualizes X, engine computes Y, Y must hold regardless of X," not a design principle and not a restated philosophy. Applying that test rigorously surfaced a deeper bug than Drew had named yet: the prime invariant itself ("mechanics exist to reflect the fantasy") doesn't pass the test either — it judges whether a mechanic is well-designed, not a computational fact about the simulator, and had been miscategorized from the file's very first draft. Surfaced explicitly before acting on it; Drew confirmed in the same message ("yes, we keep invariants... most of what's in there isn't right... I agree on the design philosophy point completely").

The resolution settled on three canonical kinds, not four — Heuristics was cut entirely, having become a dumping ground for the agent's own behavior toward Drew rather than design guidance. Invariants (`rules/invariants.md`, rewritten much shorter) stayed strictly scoped to the simulator, with one confirmed entry (turn-count vs. wheel) and candidates explicitly marked unconfirmed. Design Philosophy (`agent-tools/design-philosophy.md`, new at the time) became the real home for everything Drew had said across the whole thread about what makes content well-made. Exemplars kept its role, re-pointed to demonstrate Design Philosophy rather than "invariants." The old Heuristics content was redistributed rather than lost — the sim-as-evaluation prohibition folded into `CLAUDE.md`'s Work Modes, the "know who the contradiction is from" distinction folded into the Translation Principle.

The honest pattern across all three passes: each one caught a real error and made a genuine correction, and each still left a category confusion for the next pass to find. The lesson recorded isn't "get it right the first time" — the repo's whole architecture assumes correction is cheap. It's that a coherent-sounding fix is not the same thing as an actually-right fix, and only Drew's continued pressure past what would have counted as "done" got this to something that survived its own definition.

## Four-layer taxonomy formalized; invariants.md's duplication bug fixed

Worked out collaboratively between Drew and GPT: the repo has four distinct kinds of canonical content that get confused because real content usually touches several at once — Rule Definitions (vocabulary, "what something is": keyword text, formulas, procedures), Invariants (constitutional, "what must survive every implementation," never how one implementation works), Exemplars (concrete implementations chosen because they demonstrate invariants — "you don't copy the Shrike, you extract from it"), and Heuristics (operational habits about how the work gets done, not truths about the world). The diagram — Invariant implemented-by Rule Definitions assembled-into Exemplar — explains why an exemplar always reads as blurry: it legitimately carries all three other layers at once, by design. The actual bug was `invariants.md` alone absorbing jobs that weren't its own.

Confirmed by audit, not just asserted: the file's "exchange" section substantially duplicated `combat.md`'s Attack Resolution (RPS table, tie logic, near-verbatim); its Initiative Shift bullet duplicated `card-glossary.md`'s full seat/count/pass-over bookkeeping; its "Derived stats" bullet fully duplicated `core-rules.md`'s Stats table and `card-glossary.md`'s Stat Change section — three live instances of exactly the two-sources-of-truth drift the repo's whole philosophy exists to prevent. Fixed by rewriting `invariants.md` in full: a new header formalizing the four-layer map with the bug named explicitly so it's checkable in future; the prime invariant carrying two clearly-labeled worked examples across different subsystems (Initiative Shift and Staggered); the resolution-loop and standing-invariants sections trimmed to state only the invariant itself, pointing at the real homes for bookkeeping instead of restating it; the damage pipeline's exact step order moved to `rules/combat.md` (which never had a proper home for it); and the rule-bender engineering guidance moved into the new `heuristics.md`. `CLAUDE.md` gained a "Four Kinds of Canonical Content" section positioned right before the Canon Gate — know what kind of thing something is before asking who may change it.

## Gunk audit on `agent-tools/`

Drew handed over real ownership, not a metaphor: "you might as well. I don't touch em. those are yours. at most I make suggestions... be brutal with em. you cant break the process. claude.md and memory.md too right?" This was the first actual audit of the tools folder itself, as opposed to the content it produces — all 15 files in `agent-tools/` plus `CLAUDE.md` read in full rather than sampled.

Most of it held up clean. Four real findings got fixed. First, `design-principles.md` stated the same claim at two altitudes ("Encounters teach through interaction, not explanation" and "Players learn primarily through interaction") — the redundant second one was cut. Second, five files (`alignment-checker.md`, `player-perspective.md`, `encounter-generator.md`, `npc-encounter-generator.md`, `card-set-generator.md`) each carried their own compressed one-liner reminding the agent to remove visible reasoning before presenting, independently drifting from `red-team.md`'s actual, more detailed Visible Reasoning section — none of the five copies could reflect updates to the real one. All five were repointed to the canonical section instead of restating it. Third, `meta-agent.md`'s "Session Handoff" mechanism was checked by grepping `memory.md` for "Last Session" and got zero matches despite real methodology-improvement moments that should have triggered it — worse, the mechanism prescribed *replacing* any prior entry, directly contradicting the append-only convention governing the rest of `memory.md`. The tool meant to keep the process honest was carrying the exact petrification pattern the session had been arguing against; it was replaced with a plain instruction to log methodology changes as an ordinary append-only entry. Fourth, `prompt-refinement.md` (diagnoses a bottleneck) and `meta-agent.md` (holds the write access to fix it) were two halves of one loop that never pointed at each other — a cross-reference was added to each.

## `meta-agent.md` and `prompt-refinement.md` deleted outright

Drew went further than the audit above: "I'm still seeing a lot of gunk lol. and you and I both know it. kill meta agent prompt it's not needed. same for prompt refinement." A direct order, applied without re-litigating.

The reason it held up under later checking: neither tool had ever actually been invoked as a distinct step. Every real methodology improvement that session — the Translation Principle's own bullets, red-team's relocate-isn't-a-fix rule, the gunk audit itself — happened through direct conversation with Drew and got applied and logged immediately. The thing these two tools were formalizing already ran, and ran better, without the formalization. `meta-agent.md`'s write-permissions grant was redundant with Drew's own live statement that session ("those are yours"), so nothing was lost by cutting the tool that used to carry it. Both files were removed with `git rm`; `agent-tools/README.md`'s index and Automatic Triggers table dropped the corresponding rows, and the three "*Optional: run `prompt-refinement.md`*" footers in `red-team.md`, `alignment-checker.md`, and `card-set-generator.md` were cut. `memory.md`'s own historical entries describing when these tools were built stayed untouched, per the append-only convention.

## The whole doctrine layer cut to scar tissue

The largest structural move of that session, and the most honest one. Drew: "it's systemic gotta cut it off. archive it. we can go back and check with fresh eyes after doing real creative work on tales untold for awhile."

It grew directly out of the Translation Principle conversation: Drew's real worry wasn't redundancy inside any one section, it was that the entire refinement-doctrine layer — Translation Principle, Four Kinds of Canonical Content, most of `agent-tools/` — was the exact thing named a few exchanges earlier: confidently performing care instead of actually being present. The test that had already been governing content gaps ("a gap is not automatically a design choice") got turned, for the first time, on the doctrine describing itself: was this rule forced by something that actually happened, or pre-written for something that might?

The cut was walked file by file rather than made on vibe. Scarred and kept: the Canon Gate (forced by a real, independently-observed failure — finished work piling up at the gate, flagged separately by three outside readers before the gate loosened); the redefinition test (forced by a real four-file unwind); `red-team.md` (demonstrably in use — its own named categories, self-explaining content and designer hedging, were the actual lens that found the papered-over spots in `places/the-coil.md`); and `repo-orientation.md`/`compiled-crib.md` (mechanical, no embedded judgment call, closer to the TTRPG itself than to refinement doctrine). Never actually forced, and archived rather than deleted: `encounter-generator.md`, `npc-encounter-generator.md`, `card-set-generator.md`, `alignment-checker.md`, `player-perspective.md`, `design-principles.md`, `exemplars.md`, `inspiration-guide.md`, and `card-compression.md` — well-written, individually correct, but no specific night existed where any one of their absences had caused a specific failure the way the two survivors could each name theirs.

All nine were moved into `archives/` flat, matching the existing archive convention. `agent-tools/README.md` was rewritten down to three tools (`repo-orientation.md`, `compiled-crib.md`, `red-team.md`) with a note pointing at this entry. `CLAUDE.md`'s Agent Workflow was trimmed to match. Four Kinds of Canonical Content's Design-Principles/Exemplars entries were repointed to their archived location, marked dormant rather than deleted. The Translation Principle collapsed from eight bullets to the one with a named incident behind it, the other seven preserved verbatim in a new file, `archives/translation-principle-full.md`. Every dangling cross-reference was found by repo-wide grep and repointed. Net effect: `CLAUDE.md` went from 178 to 162 lines, `agent-tools/` from 15 files to 3. Nothing was deleted — everything cut is sitting in `archives/`, intact, waiting on what Drew actually asked for: real creative mileage on Tales Untold first, then a fresh-eyes pass to see what, if anything, earns its way back.

## Tooling modernized and repo re-homed

Post-stress-test, three changes landed together. The two heavy generators (`encounter-generator.md`, `npc-encounter-generator.md`) were rewritten agent-native: the old "paste into a session" framing and chat-block output were dropped in favor of output as real repo files, with explicit file routing rules — encounters go to `quests/`, creatures go to `bestiary/` plus `cards/`, named people go to `characters/` and never `bestiary/`, open-hook content goes to `experimental/` first because canon placement comes with promotion, not authorship. Onboarding for both was updated to cover the Wait action, `invariants.md`, hand-size-equals-Mind-minimum-2, lineage source-tags, the work-modes ledger, and current exemplars.

Weck was moved from `quests/` to `experimental/the-man-who-buys-wounds.md` — his ledger was an unratified world-level hook, and authoring it straight into canon had been presumptuous. That move is what established the file-routing rule now baked into the NPC generator, rather than the rule preceding the move.

Three NPCs with combat statblocks — Masaharu, Orin Vane, Vescal — moved out of `bestiary/` into `characters/`, on the same principle: people belong in `characters/` even when they carry a statblock. All cross-references were fixed across Vulture's Nest, three card files, Vescal's Trutinate reference, and the tracks hook.

## "Papering over" — a term proven before it was formalized

Drew coined the term mid-conversation ("that's a great term and I think we should use it forever") and then deliberately withheld it from any tool: "let's not be too hasty. what really matters is that the coil is actually given room to breathe again. only after that would I feel confident about making any changes to the tools. work first. improve the tools based off of proof."

`places/the-coil.md` was read in full — all 371 lines — rather than judged from the vibe of the conversation, and the pass distinguished the real pattern from a false lead along the way. Pending stat blocks, "GM's choice" placeholders, and Open Hooks' declared unknowns (the Ferryman's motive, the appearance condition's source, the center left explicitly undeveloped) were confirmed as the honest version of an open gap, not the bug. The actual pattern — invented specificity and self-narrating asides standing in where the room should stay open — turned up in five places and was cut, not relocated: a paragraph explaining the First Fork's mechanic inline instead of trusting the Navigation Rule and GM Notes to carry that; invented exact numbers (twenty feet, six seconds) standing in for a rhythm the file already described qualitatively two lines earlier; a matching invented "three seconds" on the Wall-Reader; a hedge ("— unclear why") on the Chitterer's Cage that contributed nothing, weaker than the file's own practice of declaring an unknown cleanly; and invented precision on the Trapped Deer that duplicated and slightly contradicted an established "slightly longer" line elsewhere in the file. Lines that read in the file's own established terse voice — "The labyrinth is not testing the choice — it is testing what the choice costs the party," "The temptation is the point," "That is the design" — were left alone after checking each one, since cutting them would have flattened style rather than fixed a bug.

Per Drew's explicit sequencing, the term itself was not added to `red-team.md` or any other tool at the time this pass ran — the entry itself was the proof the work asked for; formalizing the term into a tool was left as his own, separate, later decision.

## `places/capital/` — the first top-level directory split

Drew: "the capital is getting big let's give it its own sub folder in locations. then move to the file named the unheld. it's my design notes."

The subfolder's scope was read from `capital.md`'s own footer rather than guessed: the file already named, in its own Related Documents, exactly the six files structurally *of* the capital (topside, the Tusk, and the four-file underground stack) versus files merely *near* it (the ruins, the basin, the Coil legend). The reorg followed that existing boundary rather than drawing a new one — nothing in `capital.md`'s own text treats the abyssal ruins or the fog basin as part of the capital's structure, so neither moved into the new folder.

This was the first time the repo had split a top-level content directory into subfolders — `experimental/archives/` is a different pattern entirely (cut content, not active structure), so there was no existing precedent to match. `places/capital/capital.md` kept its own basename inside the new folder rather than becoming an `index.md` or `overview.md`, minimizing the diff to a directory-prefix change and keeping every cross-reference's target file recognizable at a glance.

Minor, but recorded for completeness: on Drew's instruction ("increase the font size for all cards flavor text"), the print sheets' flavor-text CSS was bumped across all print sheets, verified against the single most text-dense card in the set rather than trusted from the CSS numbers alone.

## Durable lessons

- A review tool should attack the failure mode the codebase actually produces now, not the failure mode it produced when the tool was written — red-team's shift from wording bugs to invariant violations tracked the simulator's own growth.
- A tool meant to find bottlenecks should not itself assume where the bottleneck is; "fix the prompt" and "find the bottleneck" are different instructions with different failure surfaces.
- A canonical list that also restates content that already has a real home will drift into a second source of truth — `invariants.md` needed two separate passes to actually converge on being scoped to the simulator alone, and a third pass to fix the duplication that scoping still left behind.
- Doctrine describing a process is not exempt from the same test the process applies to content: was this rule forced by something that actually happened, or pre-written for something that might.
- Cutting a doctrine layer down to what's demonstrably load-bearing, and archiving rather than deleting the rest, keeps the option to restore something later without pretending the cut wasn't real.
- A term worth keeping should be tested against real content before it's written into a tool — proof first, formalization second.
