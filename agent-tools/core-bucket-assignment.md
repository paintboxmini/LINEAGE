# Core Set Bucket Assignment

**Recorded, not executed.** Every card in the three core sets has a bucket assigned here. **No cards have been moved** (2026-08-17, Drew: *"record the assignment, don't move the cards yet"*). This file *is* the home — when the Oracle pool is slimmed, each card's destination is already decided and reviewable, and the physical split can follow without re-litigating anything.

## Why this exists

Drew: *"the goal isn't to empty the Oracle pool. it's to create buckets so that when we slim the Oracle pool down the cards have a home already."*

Three steps, in order, and the order matters: buckets have to exist before the core sets can mean "Oracle candidates only," and bestiary deck-filling cannot be repointed at buckets until there are buckets to point at. This file is step one.

## The rule

**One card, one bucket.** A bucket is a filing system, not a query. Cards routinely do two things — the assignment picks the one that carries the card's identity, not every mechanic it touches. For multi-label behavior lookup, use `agent-tools/card-corpus-analysis.md`'s design-space grid instead; that layer is deliberately multi-label and answers a different question.

Buckets name **what a card is for**, never the keyword it happens to use. Drew: *"discard by itself doesn't tell us the useful part about what a card is doing."* This is why FIELD MEDICINE files under cleansing rather than with the discard-pile cards — it heals, but what disqualifies it from a starter pool is that it removes Wounds, which presupposes Wounds exist.

### self-inflicted cost (10)

A benefit bought with a real price paid by the user — Exhaust into your own hand, HP, your own card, a skipped turn, a self-debuff. The cost is the card's identity, not a drawback bolted on.

*Archetype:* The Gambler — TABLE STAKES is its shipped example and files here. GAMBLER'S RUIN is the archetype's other shipped card but files under damage amp, since exploding dice is what it does; the archetype spans both buckets, which is exactly why archetypes are an index and not a filing system.

## Hand-assigned entries

The mechanical pass misfiled these; they are set by hand and should not be recomputed away.

- **CHAIN** → damage amp
- **CLIMB** → card flow
- **DEFLECT** → defense
- **DRAIN** → buff removal
- **LEVEL THE FIELD** → buff removal
- **SEED** → position
- **WAITING GAME** → buff removal

**The misfilings clustered on archetype cards**, which is the useful finding rather than an annoyance. SEED is The Cultivator's shipped example, GAMBLER'S RUIN The Gambler's, WAITING GAME The Mirror's. They resist mechanical sorting because their identity is a strategy rather than a mechanic — exactly the gap Drew predicted keyword sorting would leave. Where a bucket lines up with an archetype, the cross-reference is noted above; where it does not, no archetype was invented to fill the space.

## What this does not decide

- **Which cards leave the core sets.** That is the pool-slimming pass, and it has not happened. Every card listed here is still in `cards/red-body.md`, `cards/blue-mind.md`, or `cards/green-soul.md`.
- **Bucket file names or paths.** Nothing has been created. `cards/stat-adjusters.md` is the only bucket that physically exists, built ahead of this file for cards that had already left core.
- **Whether a bucket is worth being its own file.** Cleansing holds one card. That is an argument for merging it later, not for forcing a member into it now.
