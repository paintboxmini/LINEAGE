# Heuristics

Operational principles about *how the work gets done* — not truths about the fictional world (that's Invariants), not vocabulary (that's Rule Definitions), not concrete demonstrations (that's Exemplars). See `rules/invariants.md`'s header for how these four layers relate and why they're kept apart.

A heuristic tells an agent or a future session *when to act*, not *what is true*. Add to this list whenever a repeated pattern in how we work gets named — don't let it stay implicit in a paragraph somewhere it'll get lost.

---

- **Promote repeated retrieval.** If an agent repeatedly retrieves the same examples to rediscover a pattern, that pattern has earned a permanent home — promote it into `agent-tools/exemplars.md` (or wherever its layer lives) rather than re-deriving it from scratch next time.

- **Promote a rule-bender's architecture only when the current one hurts.** Today every rule-bender (Axiom, Paradox, Interrupt, Stagger, Intercept...) is a per-combatant flag read inline at one pipeline step — cheap, and sufficient so far. The agreed escalation path (`memory.md`, architecture north star) is flags → typed modifiers with lifetimes → a policy stack. Move up a level only when adding the *next* bender as a flag has become genuinely painful — not preemptively. A rule-bender that can't be expressed as (1) name the mechanic it overrides, (2) set a flag with a clear expiry, (3) read that flag at exactly one pipeline step, (4) revert on expiry, is the concrete signal that the next architecture level is due — raise it before shipping, don't route around it.

- **Do not use the combat simulator to evaluate a change.** It is a design instrument Drew consults separately, on his own schedule, for his own questions — not a verification gate for canon changes, and not a step to run reflexively when implementing a ruling. Keeping the simulator's code an honest model of current canon is still worth doing (a stale sim is its own bug); running tournaments to decide whether a ruling is balanced or safe is not this agent's call to make by default.

- **Model turn order as a list; the wheel is only ever a picture of it.** Turns-until-action is derived from a position in a list (position − 1, current actor normalized to position 1); the circular wheel exists only to make one property of a list (after the last actor, play continues with the first) easy to read at the table. A shift is a list operation — remove, reinsert X positions away, slide the gap closed. Implement and reason from the list; render the wheel from it, never the reverse.

- **A cheap experiment that gets overridden the same day is not a failure — it's the gate working.** The tier→authority-level rename, and the six-hour difficulty-tier recalibration that Strength immediately superseded, both cost almost nothing and both surfaced the right answer faster than deliberating up front would have. Prefer shipping a fast, reversible attempt over holding a decision open.

- **Mark inferred connections, don't assert them.** When a new piece of content resonates with something already established (a location's open mystery, a faction's stated purpose) but the connection wasn't stated outright, write it as a flagged, optional GM thread — not as fact. Recent instances: the Turnroot-thorns/Mason-perimeter tension in the Skeinwing's file; the ruins/fence connection before Drew confirmed it. The cost of a wrongly-asserted connection is much higher than the cost of a clearly-labeled maybe.

- **Know who the contradiction is coming from before deciding whether to ask.** When Drew states new mechanical text directly — even offhand, even mid-illustration of something else — that statement already is the ruling; his authority doesn't need a second, more formal restatement to count. Apply it, note the change plainly (queue line, log entry), and let him revert if it wasn't what he meant — that's what the Canon Gate's reversibility is *for*. Reserve "flag and ask before applying" for the different case: when the contradiction comes from *my own* inference, paraphrase, or recollection of something Drew hasn't actually re-stated — there, I might be the one who's wrong, and that's worth surfacing before building on it. Getting this backwards (asking Drew to reconfirm his own direct statement) is friction the gate exists to prevent, not caution the gate calls for.
